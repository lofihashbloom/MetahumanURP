# MetaHuman for Unity — URP prototype

`com.unity.metahuman` targets **Unity 6000.6 / URP 17.6**, desktop Metal and desktop Direct3D as intended rendering platforms. The bundled facial native plugin currently supports **macOS arm64 only**; Windows/Intel native binaries and player builds are not validated. This is an independent integration, not an official Unity or Epic package.

## New in exp.17 — hair-to-skin receiver shadows

Hair now darkens the skin it covers. Before this change, skin under Ada's coily hair was lit as if bare, so the roots read as brown skin, unlike Unreal. `HairReceiverShadowFeature` + `HairReceiverShadowVolume` bind up to four static light-space optical-depth fields built from the source groom by `Tools~/Hair/build_receiver_shadow_fields.py`; skin materials opt in with the local `MH_HAIR_RECEIVER_SHADOW` keyword and attenuate each mapped direct light once. In the controlled Ada comparison, the hairline error against Unreal drops by about 12–16%. Fields are rest pose (no head motion, deformation or moving lights) and model fibers as gray occluders. Setup, requirements and validation: HairReceiverShadows notes (not part of this repository).

Face and body animation: `DnaRigDriver` applies the rig's corrective blend shapes and drives wrinkle maps (`DnaAnimatedMapBinding`, skin keyword `MH_ANIMATED_MAPS`). With `layerBodyJoints`, neck and head deltas layer on the body animation instead of overriding it. `GroomSurfaceBinding` makes eyebrow strands follow the deforming face skin. Scalp hair can be parented rigidly to the head bone; receiver shadow fields are rest-pose fields, so on a moving head they keep the light direction fixed in head space. None of this is Unreal groom binding, simulation or full RigLogic parity.

## Current state — exp.16 hair work

The new optional `Roughness037Envelope` local-scattering profile uses an independently fitted angular response, validated against fresh unit renders before the long-hair comparison. It reduces long-hair Local RGB error about **69–71%** and Full error **6–7%** versus exp.15, with unchanged optical coverage. Full mean brightness remains **3.5–4.4%** above the matched raw reference. The profile is restricted to constant authored roughness0.37; the old profile1 and default-off behavior remain available. Input-format adaptations that worsened broader checks were rejected.

The new long-hair local-plus-temporal preset reduces fixed-region error about67% versus exp.15 AA0 when both are compared with the matched native TAA reference. This combines scattering and reconstruction changes; it is not a TAA-only improvement. Remaining temporal mean brightness is4.7–5.3% high, including the explicitly measured neutral post-LUT residual.

The optional groom temporal path supplies covered hair depth and rigid velocity to URP TAA. Continuous-frame validation checks actual history advancement, jitter, camera movement and rigid geometry motion. `GroomTemporalHistory` resets history on cuts and explicit geometry changes. See temporal setup and limitations notes (not part of this repository). Deformed previous control points, wind and hair-specific history rejection remain unfinished.

`GroomLodController` adds explicit strand/card selection with projected screen height, hysteresis, camera policy, renderer-state restoration and TAA invalidation. Automatic selection defaults off, with a strand fallback when cards are missing or invalid. `GroomLodSetup` configures existing representations; `GroomClusterCardBaker` provides an experimental static source-projection bake. The host's denser512-card fiber-lit experiment remains outside the package and disabled: distant coverage is still10.9–13.3% below strands, so it is not a production LOD or native card renderer.

The exp.15 compensated-rectangle raster profile remains optional. Measured source flags/resources establish one effective native Mac visibility sample even when eight are requested; no native raster implementation or scattering LUT coefficients are copied. Kellan and the original shoulder-length fixture retain matched single-sample settings. Generic defaults remain `AnalyticArea`/`WeightedAll`, local scattering off, and temporal reconstruction off. The optional source coverage channel requires `GroomRasterSetup.ConfigureRectangle` validation for every sharing mesh; channel3/TEXCOORD3 is the fourth UV set (`Mesh.uv4`).

Static/rigid Mac reference improvements do not establish pixel-perfect parity, shadows/IBL, native automatic LOD, binding/simulation, broad roughness, deformed-motion or Windows/player support. The long hairstyle is an original procedural fixture anchored to Kellan's scalp, not an Epic preset. Character data, scenes and captures stay outside this package.

## Source-data tools

`Tools~/Unreal/export_character.py` uses public Unreal export APIs, checkpoints source hashes/material metadata, records resolved static switches and preserves supported source image precision through TGA/PNG/EXR dispatch. Those source images do not automatically include native texture build compositing. `Tools~/Unreal/bake_eye_occlusion.py` validates inspected graph connections/UV0 and evaluates two linear optical lookup PNGs into a separate `*-Optics.mhmanifest.json`, leaving the raw manifest and original assets unchanged. Temporary material copies are never saved; parameter changes require rebaking the lookups.

[TextureExportBridge](Tools~/Unreal/TextureExportBridge/README.md) is an original Editor-only public-API helper for unchanged BC1/3/5/7 platform mip export, with format/block/mip/hash validation and compositing-source provenance. Use a dedicated RHI-enabled `-run=pythonscript -AllowCommandletRendering` process; `-nullrhi` cannot supply the required skeletal/platform data. Native profiles, material values and encoded textures are character data, not copied Unreal renderer implementation. Meshes, DNA, textures, lookups, generated scenes and captures remain in the host outside the code package and retain their source licensing.

## First import

1. Export a character using `Tools/Unreal/export_kellan.py` in this prototype host. It uses Unreal's FBX and texture exporters and writes a versioned `.mhmanifest.json` with SHA256 receipts. The script reads source assets without saving changes to them. Rendering must be enabled for skeletal FBX export.
2. Keep the entire exported directory under your Unity project's `Assets` folder. Select its `.mhmanifest.json`, then **Tools > MetaHuman > Import Selected Manifest**.
3. Select the generated prefab, then **Tools > MetaHuman > Create Look Development Scene From Selected Prefab**. Save prompts protect an existing modified scene. This command creates a new portrait scene and sets it as the build scene; it also enables HDR, 4x MSAA, unlimited skin influences and a 20 m shadow distance on the active URP asset.

Generated assets live under `Assets/MetaHumanGenerated`. `ImportReport.json` records material assignments and warnings. Reimport overwrites generated materials and the prefab; keep manual variants separately. Texture import settings on the source bundle are also updated.

To use the package in another compatible Unity project, choose **Package Manager > Install package from git URL** and enter `https://github.com/lofihashbloom/MetahumanURP.git?path=/MetahumanURP` (append `#<tag or commit>` to pin a revision), or choose **Install package from disk**, selecting this folder's `package.json`. The embedded package has no dependency on the host, its assets or Pipeline tooling. The `com.unity.*` identifier was requested for this experiment; it does not imply registry publication or Unity ownership.

The distributable also includes `Tools~/Unreal/export_character.py`. Run it through Unreal's Python commandlet with `-AllowCommandletRendering` (not `-nullrhi`). Set environment variables `METAHUMAN_SOURCE_ROOT=/Game/MetaHumans/MyCharacter` and `METAHUMAN_EXPORT_DIR=/absolute/path/to/UnityProject/Assets/MetaHumanSource/MyCharacter` to select the character and destination. With no destination, it exports into the Unreal project's `Saved/MetaHumanExport` directory. This exports existing assembled assets; character creation remains in MetaHuman Creator.

## Implemented

- Manifest validation, file hashes and path containment before import; errors reject incomplete exports.
- FBX skeleton and morph preservation, resolved Unreal LOD section material remaps (including the skeletal FBX exporter omission), imported normals, MikkTSpace tangents, up to 12 bone influences per vertex, unoptimized joint hierarchies.
- Per-texture color-space/format/size metadata; source-size desktop import (including 8K source maps); explicit per-map orientation handling and optional native BC1/3/5/7 mip transport.
- Skin with URP PBR, two weighted specular roughness lobes, local transmission and fuzz approximations. UE dielectric specular is converted to F0 with `0.08 * Specular`.
- Explicit packed-mask layouts. Modern SRMF uses R specular, G roughness, B metallic and A fuzz. Legacy simplified skin is recorded as `LegacySRM`: R cavity response, G roughness; alpha is not fuzz. Separate scalar maps remain supported. Raw source controls are preserved in the manifest.
- Full-normal wrinkle map blending through `_WrinkleWeights`. This mode expects complete tangent-space normal maps, **not animated delta textures**. No wrinkle maps are assigned automatically.
- Eye PBR with independent sclera/iris textures, source color lookups, pupil dilation, limbus and an approximate recessed-iris refraction model. Two-sided alpha-tested hair cards with a tangent-directed highlight; matched alpha clipping in depth, normal and shadow passes.
- Forward/Forward+ light loops, real-time shadows, probe ambient, fog, instancing and stereo vertex plumbing. `UniversalForwardOnly` keeps these surfaces forward shaded under a deferred renderer.
- Explicit named-control-to-blend-shape mappings in `FaceMapping` and `BakedFaceDriver`. Inputs sum, clamp and clear deterministically without editing shared materials. Unknown shapes are skipped; there is no automatic ARKit or DNA mapping.
- A saved portrait stage with three-point lighting and an ACES Volume; validation and PNG capture helpers.


## Historical: native DNA facial animation (v0.1.0-exp.2)

`DnaRigDefinition` holds a standalone binary DNA `TextAsset` (use a `.bytes` extension). `DnaRigDriver` owns an independent native instance and exposes `SetRawControl(name, value)`, `ClearControls()` and `EvaluateNow()`. In Play mode it applies outputs in `LateUpdate`; optional Editor preview can be enabled explicitly. Raw names are exact DNA names such as `CTRL_expressions.jawOpen`, not automatically mapped ARKit names or GUI faceboard controls.

The bridge uses Epic OpenRigLogic **5.8**, riglogic4 **13.2.9**, commit `d3d329bbd6992ac38adc1c1b24203ceb998f75c0`. It loads neutral transforms, evaluates joints, morph-channel values and animated-map values at a requested DNA LOD. The present Unity driver applies joint outputs; morph-channel and animated-map arrays are exposed but are not automatically bound to mesh shapes or shader masks.

The supported `LegacyUnrealFbx` conversion is translation `(x,z,y) * 0.01` and quaternion `(-x,-z,-y,w)`. Before accepting a rig, the driver validates every driven joint's name, hierarchy and neutral pose against the FBX (maximum 0.1 mm position / 0.1 degree rotation discrepancy). The DNA root is kept under body-animation ownership because its DNA transform can be global while the FBX attaches it below the body spine. Unsupported coordinate conventions fail explicitly.

Kellan's verified data has 647 DNA joints, 646 driven descendant joints, 269 raw controls, 82 animated-map outputs and four DNA LODs. All neutral bind transforms passed validation. This does not establish animated-pose or image parity with Unreal.

The existing Kellan asset contains a standalone legacy behavior stream. `Tools~/Unreal/extract_legacy_dna.py --asset <Kellan_FaceMesh.uasset> --output <bundle>/DNA/Kellan.behavior.dna.bytes --manifest <bundle>/Kellan.mhmanifest.json` recovers that stream with source offset, length and SHA256 provenance. It deliberately supports only the verified uncooked v2.1 behavior / v2.4 geometry serialization layout. It is not a general `.uasset` reader and does not replace DCC Export for newer characters. Native parsing and neutral-pose validation remain mandatory.

A manifest can reference a compatible standalone DNA using `"dna": {"file": "DNA/Character.dna.bytes", "sha256": "...", "coordinateConvention": "LegacyUnrealFbx"}`. The importer verifies its hash, generates a definition and binds the driver. It disables that component with a warning if the native library is unavailable on the current platform. Reimport no longer removes an attached DNA backend.

Open the host's saved portrait scene and press Play to cycle neutral, jaw open, blink, smile and brow raise. The `DnaExpressionSequence` component is a small explicit raw-control example; remove it when another animation or capture system owns those controls. Only one system should own a joint/control stream at a time. Initialize the driver in the imported neutral bind pose, before another animation system modifies its joints. Synchronizing separate face/body skeletons is still integration work.

### Rebuilding the native plugin

Fetch the pinned OpenRigLogic 5.8 commit separately, then run `Native~/build_native.py --source <checkout> --build-dir <build> --output <library> [--cmake <cmake executable>]`. CMake, a C++ compiler and Python are required. The script rejects a different source revision and does not download or install tools. Close Unity before replacing a loaded native binary. `Native~/CMakeLists.txt` is also usable directly with `-DOPEN_RIGLOGIC_SOURCE=<checkout>`.

The bundled binary is enabled only for the macOS arm64 Editor and player. The C ABI and CMake source are portable, but source portability is not a Windows/Intel validation claim. See `Third Party Notices.txt` for the OpenRigLogic MIT license. No character DNA or meshes are included in the package archive.

## Historical: bound hair cards (v0.1.0-exp.3)

The importer now builds face-surface bindings for available static hair-card meshes. It spatially fits vertices to the largest face section with a 0.7 mm minimum clearance, records triangle/barycentric attachments and stores readable fitted meshes under the generated character's `Bindings` folder. The original FBX renderers are disabled; generated bound renderers preserve materials and active/inactive LOD alternatives. Vertices farther than 5 cm from the face reject the automatic fit rather than silently snapping a different hairstyle.

`CardSurfaceDeformer` runs after facial animation, bakes the face once for all active groups, and updates card positions, normals and tangents using triangle frames. The CPU baseline preserves the defined surface attachment under joint or morph deformation; it is an independent implementation and does not reconstruct Epic's groom binding asset. Rest fitting is a spatial approximation, not source-groom transfer parity. A future GPU implementation can reuse the stored attachments.

For Kellan, both eyebrow-card alternatives have bindings; the active LOD1 has 3,670 vertices. Mean rest fit distance was about 3.8 mm and maximum under 8.4 mm. A brow-raise test moved the cards by about 8 mm while leaving fitted mesh assets unchanged. The active CPU reference update measured about 1 ms on the local Apple M5 Editor over 20 repeated iterations, including face baking and mesh upload; this is not a standalone-player frame-time claim.

The hair shader stabilizes fine-strand alpha-to-coverage with screen derivatives. Depth and normal passes use matching coverage, and the extra hair highlight uses the same UE-specular-to-F0 scale as the surface shader. Eyebrow materials use a lower cutout threshold and reduced specular response to preserve fine hairs at portrait resolution. Tangent-atlas decoding and physically complete strand scattering remain unimplemented.

The desktop look-development baseline now uses `SkinWeights.Unlimited`; the first baseline stored 12 influences but rendered with a four-bone limit. The mobile quality tier is unchanged. Bindings target one exact face mesh/LOD and must be regenerated when its topology changes. Editor previews use transient mesh clones and restore generated rest assets before scene or Prefab Stage saves.

## Historical: skin diffusion and eye shading (v0.1.0-exp.4)

Run **Tools > MetaHuman > Enable Skin Diffusion On Active Renderer** after importing. This adds one `SkinDiffusionFeature` to the active Universal Renderer asset and serializes its fullscreen shader reference. The host's portrait renderer already includes it. It uses URP 17.6 Render Graph and runs before transparents, so wetline and eye-occlusion geometry composite afterwards. Overlay cameras, reflection/preview cameras and stereo cameras are skipped. XR and dynamic-resolution behavior are not validated.

Skin has an explicit `_DiffusionAmount` (enabled by the importer for head/body/skin materials; disabled for teeth/cartilage). A depth-tested extra skin draw writes diffuse lighting, material amount, geometric normals and linear eye depth. The diffuse term is extracted by subtracting the same BRDF's specular-only lighting from its full lighting. Horizontal and vertical 13-tap filters use different RGB widths, with depth, normal and skin-mask rejection. Resolved normal length estimates MSAA coverage, so lighting/depth are unpremultiplied before filtering and coverage is restored at composite. Guide and lighting taps use the same texel, preventing pre-filtered non-skin samples from darkening contours. The final pass adds only the diffuse change back to camera color; it does not blur specular, fuzz, eyes, hair or the background. Texture handles are passed explicitly; material property blocks bind the resolved inputs during graph execution without publishing global textures.

The default profile uses a 3 mm maximum support radius, strength 0.65, 1.5 mm depth rejection and normal-dot threshold 0.6. Radius projects with distance, projection type and image resolution, capped at 40 pixels. That exp.4 mode was a separable screen-space approximation with a heuristic RGB profile. The current source-profile adapter and normalized radial option are described above; neither transports light through unseen surfaces. Thickness, temporal behavior and GPU/player cost still need broader measurement. The extra skin draw, floating-point targets and full-resolution filtering favor a desktop quality baseline over low cost.

The exporter now records resolved scalar/vector parameters as well as texture bindings. Skin imports the source `MinRoughness`, `MaxRoughness` and `SpecMult` values. Eye import binds the grayscale iris, sclera/vein map and the existing iris/sclera color lookup textures. Lookup uniforms retain source UV values; their V coordinate is reflected when sampling Unity textures. Kellan's source values include iris diameter 0.32, pupil scale 1.12, IoR 1.336, roughness 0.10 and sclera brightness about 0.472. The host records the read-only source extraction in `Validation/UnrealMaterialReference.json`.

Eye shading adds a limbal transition, radial pupil remapping, source iris color/contrast and view-dependent refraction into an approximate recessed iris plane. A smooth geometric corneal normal and IoR-derived Fresnel response preserve sharp reflections independently of iris detail. `_IrisDepth` is explicitly a UV-space approximation, not physical corneal thickness. In this exp.4 baseline the underlying surface stayed opaque without camera-color sampling. The current legacy occlusion layer additionally filters a scene-color snapshot; that does not create anatomical corneal geometry. The source iris brightness boost is applied as a bounded albedo multiplier, not as a reproduction of Epic's caustic/lighting model. The implementation does not reproduce the full eye material graph or all color-correction parameters. Anatomical corneal geometry, iris caustics and full eye matching remain future work. The legacy eye profile in exp.5 uses its source normal map for reflection; IoR controls iris refraction separately.

`EyeOverlay` replaces the generic white transparent eye rims. Occlusion mode uses a soft UV-edge attenuation mask and zero reflected/emitted color. Wetline mode uses a restrained, premultiplied dielectric reflection with IoR-derived Fresnel opacity. The two overlays draw after diffusion and do not write depth or cast shadows. This is an independent UV/film approximation, not Epic's lid-dependent occlusion graph or physical tear geometry.

GPU integration tests render a patterned skin surface behind a blue opaque occluder, check visible skin diffusion while preserving the foreground, preserve a specular-only sphere highlight and a uniform surface's 4x-MSAA silhouette, verify that pupil/refraction controls change the iris, and ensure eye occlusion attenuates without adding light. The host captures front/three-quarter on/off comparisons plus eye closeups. These checks establish operation and isolation, not visual parity with Unreal.

## Historical: matched Unreal reference (v0.1.0-exp.5)

The host now captures native Unreal 5.8.4 and Unity scene-linear EXRs from the same neutral geometry, camera and direct lights, including front and 25-degree views at 1200 square pixels. Grooms, ambient lighting and shadows are omitted in both captures to isolate skin and eyes. An 18% emissive card normalizes exposure; a separate diffuse card checks light-unit conversion. A shared fitted ACES/sRGB transform is applied only for viewing. The largest residual channel difference on the diffuse calibration card is about 2%; image errors are measured before the display transform.

Base-color checks and roughly one-degree normal agreement ruled out a broad color-space or normal-sign error. The import correction interprets the legacy skin cavity response before converting specular to F0, retains body packed roughness, disables nonexistent alpha fuzz and suppresses uncalibrated local transmission where no thickness/scatter map exists. Kellan's head uses cavity power 4 and body 2.5 from their respective source controls. This first-order model does not reproduce the original view-dependent material graph.

The legacy eye profile converts source brightness-boost units and reciprocal iris-pattern scale, supports a uniform iris-color balance, and retains the source normal-map/specular response instead of forcing the smooth corneal override. Raw controls stay unchanged in the manifest. Under the fixed front rig, scene-linear RGB RMSE decreases by 60–89% across four preselected skin regions and 33–48% across two eye regions relative to exp.4. These local metrics do not establish full-image or animated render parity. Lid occlusion, wetline brightness and anatomical corneal response still differ visibly.

Reproducible host scripts, camera/light receipts, calibration values, fixed image regions and before/after EXRs are under `Tools/QA`, `Tools/Unreal` and `Validation/MatchedReference`. The separate `MatchedReference.unity` scene preserves the comparison rig. The portrait animation scene retains its own environment and eyebrow cards. Reference-only shader variants expose base color and world normals; they are disabled in ordinary rendering.

Unreal source and original asset parameters were studied as behavioral references. The Unity shader and filtering implementation are independent; Unreal renderer source and material graphs are not shipped in this package. Epic character content and diagnostic captures remain outside the package archive.

## Historical: first original-groom hair pass (v0.1.0-exp.6)

The package now has a strict `MHGRM001` curve reader, deterministic ribbon builder and independent `MetaHuman/URP/GroomStrands` shader. An original read-only Unreal Editor bridge in `Tools~/Unreal/GroomExportBridge` exports `UGroomAsset` source positions, widths, groups, root UVs and guide flags through public APIs. It exports source data, not Unreal renderer geometry or shader code. The helper was compiled against Unreal 5.8.4 for macOS; its compiled Unreal plugin is not in this UPM archive.

Kellan's original `Hair_S_360Waves` contains 122,113 render strands and 1,575 guides, with 1,740,959 total source points. The source `.uasset` hash is unchanged after export. A neutral-scalp check of 17,445 roots found median distance 0.14 mm and maximum below 0.8 mm. The preview retains that original rest shape and attaches the generated batches rigidly to the neutral head. It does not rebuild Epic's binding or add simulation/facial skinning.

The full-density host preview uses all render strands, skips guides and caps each curve at 12 retained source points. It produces 2,733,938 vertices and 2,489,712 triangles in 46 batches. This is a high-cost correctness prototype; GPU cost and standalone builds are not measured. The group diameter overrides and linear root/tip scales are imported explicitly; original per-vertex width variation is not yet reproduced. The color is provisional dark brown, not source melanin matching.

Ribbons expand towards the camera in the vertex shader. Longitudinal two-lobe cylinder shading and SH ambient lighting provide the first independent baseline. Spatial stochastic coverage lets overlapping subpixel strands accumulate opacity; MSAA handles rasterized edges. This first version can look grainy and shimmer as the camera moves: temporal filtering and a proper strand-visibility model remain open. Depth-only coverage matches the forward pass. Shadow casting, deep opacity, multiple scattering, strand motion vectors and coherent LODs are not implemented. Keep character/head transform scale at one for this initial physical-width convention.

The host's `GroomPreview.unity` and `Tools/QA/BuildGroomPreview.cs` exercise the public reader/builder API. This first API pass is separate from automatic `.mhmanifest.json` import; imported characters do not acquire head hair automatically. See the bridge README for build/export instructions. Character curves and generated meshes remain outside the code package. GPU regression tests check that layered subpixel strands increase coverage and remain occluded by an opaque foreground; format tests reject corrupt ranges, truncation and nonfinite points.

## Historical: matched eye diagnostics (v0.1.0-exp.8)

Kellan's actual simplified eye material uses Unreal Default Lit, not its Eye shading model. The new native closeups isolate cartilage, tear film, eye occlusion, base color and normals under the matched direct-light rig. The importer now preserves fully discarded constant opacity masks, respects hair-card opacity (including zero-opacity lower-LOD lashes), and imports the tear film's opacity .01, roughness .2, metallic 1 and specular .008. Metallic film opacity is applied once; its BRDF evaluates Fresnel independently.

The independent iris model aligns the texture's existing black aperture with the requested pupil and stretches the surrounding annulus. Source brightness boost remains 8; the explicit `_IrisResponse` .15 and neutral `_PupilRadius` .45 are Kellan-reference calibrations for the legacy simplified profile, not recovered Unreal equations or a fit validated across characters. Reciprocal texture scale and source pupil control remain explicit. The old .23 neutral pupil is the default for other profiles. Native renderer source/material graphs were analyzed only as behavioral references and are excluded from this package.

`Validation/EyeMatched` in the host contains the matched EXRs, isolated layers, material diagnostics, three-column comparisons and fixed-region measurements. ## Historical: continuous hair and source-profile skin (v0.1.0-exp.7)

Run **Tools > MetaHuman > Enable Continuous Groom Transparency On Active Renderer**. This installs `GroomTransparencyFeature` after skin diffusion and selects continuous mode on imported groom materials. `_CoverageMode = 0` retains the stochastic fallback; `_CoverageMode = 1` requires the renderer feature. Reflection/preview/stereo and overlay cameras are skipped, so use fallback mode where this feature is unsupported. The first implementation targets desktop base cameras with URP 17.6 Render Graph.

The new pass draws fine ribbons against read-only opaque depth into weighted radiance and summed optical depth targets. No stochastic fragment rejection is used in continuous mode. A separate composite evaluates transmittance and combines the weighted hair color with the camera color. It preserves opaque foreground depth and camera alpha, and leaves skin, eyes and eyebrows out of the accumulation. This removes the correlated-MSAA and spatial-noise problems of the first pass. It is an order-independent transparency approximation, not Epic strand visibility or multiple scattering. Resolved MSAA optical depth approximates partial sample transmission; colored layers are averaged rather than sorted. Other transparent surfaces composite afterwards, so arbitrary transparent intersections are not solved.

An independent black-hair/white-scalp check compares the 1200px result against an area-resolved 2400px continuous render of the same source curves. Coverage RMSE falls from 0.2343 to 0.0448, about 81%, in the fixed scalp region. This measures coverage integration, not Unreal shading parity or moving-camera stability. Source curve count, diameter overrides, 12-point limit and rigid head attachment are unchanged.

The host now has native Unreal 5.8.4 hair references with the same neutral rest geometry, source `MI_Hair` assignment, front/25-degree cameras and calibrated direct lights. The source project disables hair globally; the capture uses a process-only override, forces strand LOD0, disables simulation and preserves the `.uasset` hash. The native capture advances a persistent view through 120 actual frames per stage with temporal AA and 8 visibility samples; Unity uses continuous analytical coverage without TAA. Those antialiasing methods differ and are recorded explicitly. Grooms use their original unbound rest shape in both engines; this is not groom-binding validation. Shadows, ambient light and independent eyebrow grooms are omitted to isolate head hair. `Validation/GroomMatched` contains scene-linear EXRs, calibration, coverage checks and side-by-side comparisons. Native warm grazing highlights and Unity's broad highlights still differ significantly.

Skin diffusion now separates diffuse reflectance from illumination before filtering and restores local reflectance afterwards. `_MHAlbedo` is a depth-tested, MSAA-aware third extraction target; an albedo floor prevents division instability. `albedoPreservation` can range from the previous radiance blur (0) to full surface-color preservation (1). Fine freckles and albedo detail therefore survive uniform lighting while spatial lighting changes still diffuse. The skin shader/importer also support the previously unused tiled micro-normal texture with the source detail controls and Unity's reoriented-normal blending utility.

The exporter preserves optional `subsurfaceProfile` metadata. Source relative roughness scales and lobe mixing replace the prototype's fixed secondary lobe when present. In exp.7, `SkinDiffusionSetup.ApplyProfile(record)` used declared centimetre RGB lengths in a Gaussian approximation and retained the Burley/albedo/world-scale fields without their radial mapping. The current adapter selects the independent published normalized radial model for Burley profiles and maps the source mean-free-path convention and world scale; call `AssetDatabase.SaveAssets()` after setup. Transmission, boundary profile interactions and native temporal reconstruction remain incomplete. See [Epic's profile reference](https://dev.epicgames.com/documentation/unreal-engine/subsurface-profile-shading-model-in-unreal-engine) and [Christensen/Burley's normalized-diffusion paper](https://graphics.pixar.com/library/ApproxBSSRDF/paper.pdf) for the distinct underlying models; no Unreal renderer code is copied.

Kellan's source head profile has relative roughness scales 0.73/1.33 and lobe mix 0.85. The exp.7 Gaussian length inputs were approximately 0.260/0.080/0.037 mm using the documented centimetre units; that experiment retained `WorldUnitScale` without remapping; the current adapter now consumes it explicitly. The fixed no-hair front test improves forehead and cheek RGB RMSE by 9–23% over exp.6, while the neck region worsens about 7%. All regions remain in the report. This is a measured step towards matching, **not pixel-perfect skin**. Whole-image, varied-lighting and animated comparisons remain necessary.

The exp.7 Editor/GPU checks passed locally on Metal. Coverage/transmission/foreground tests exercise both 1x and 4x MSAA, and the skin test verifies sharp reflectance under uniform irradiance plus diffusion of varying lighting. Standalone player, Windows, GPU cost and temporal stability remain unvalidated. Captures and original character content stay outside the UPM archive.

## Reference workflow

Use the same neutral pose, camera transform, framing, lighting and exposure in both engines. Capture neutral, smile, jaw open, blink and a neck-turn frame from front and three-quarter angles. Review base color, world normals, roughness and specular separately before comparing the combined beauty render. Report image differences and frame costs after matching color transforms; visual resemblance alone is not proof of parity.
